Case viewer refactor findings

1. Split NeuroCadeCaseViewer.tsx. It currently owns pane registration, refresh scheduling, windowing, native drawing, debug hooks, layer panel UI, drag reorder, and toolbar wiring. Extract viewer state hooks and presentational layer/drawing panels.

2. Isolate NiivuePane reconciliation. The performance-focused effects are useful, but source reconciliation, hidden-layer loading, visibility sync, appearance sync, windowing sync, order sync, and surface sync should live behind a dedicated hook/module with explicit inputs.

3. Centralize layer construction. Layer defaults are duplicated between runtime command loading and output artifact conversion. Use one shared builder/defaults module for opacity, colormap, render flags, LUT handling, surface thresholds, and display mode.

4. Put direct Niivue mutations behind a smaller adapter. Viewer code currently reaches into interop volumes, meshes, drawing bitmaps, scene state, and private-ish Niivue fields from multiple places. A typed pane handle or adapter would make the imperative boundary easier to audit.

5. Split useCaseWorkspaceController.ts. It mixes case loading, logs, polling, FastSurfer run state, uploads, title cache, persistence, notifications, and routing. Separate active-case loading, run control, upload actions, and persistence/refresh concerns.

6. Remove duplicate case refresh scheduling. The controller has both a five-minute interval and a one-shot five-minute timeout for fetching cases.

7. Make viewer dependency keys testable. The synthetic keys used to avoid expensive Niivue updates should be pure exported helpers with focused unit tests so future fields are not missed silently.

8. Add tests around layer defaults, persisted layer restore, render ordering, and reconciliation key changes. The timing test catches performance regressions but not default-policy drift or missed dependency fields.
